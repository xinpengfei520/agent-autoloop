# Agent Autoloop 架构解读

日期：2026-11-04。这是对当前仓库的阅读笔记，不是协议正文。协议以 [protocol.md](protocol.md) 为准。

## 它在做什么

中台是一台确定性的工作机器，Agent 只是被雇来的进程。模型负责判断和动手，控制面负责记住、派活、限权和跟人打交道。

对外只有三个口子：来源把世界变成事件，接单程序把一轮活交给一个进程，通道把卡片送给你。内核自己不连接任何东西，也不知道 Claude、GitHub 或飞书这些名字。`tests/purity.test.ts` 把这件事钉成了测试：内核里不能出现产品名、对外请求、时钟、随机数和界面。

里面只有六个词：

| 词 | 寿命 | 作用 |
|---|---|---|
| 事件 | 永久追加 | 世界上发生的一件事 |
| 规则 | 写在文件里 | 唯一的指令：交给谁、在哪、什么权限 |
| 事项 | 跨很多轮 | 同一规则下的同一个对象 |
| 一轮 | 一次执行 | 领一批事件，交一份回执，然后结束 |
| 回执 | 一轮的最后一条消息 | 中台要做的事，一个事务里一次生效 |
| 卡片 | 直到被回答或结案 | 唯一会打断你的东西 |

一轮会结束，事项会继续。等人的时候没有 Agent 进程，也没有 Token 开销。

## 设计得好的地方

### 控制面是纯函数，模型在环外

`decide(view, input, now, environment)` 只根据传入的视图、输入、时间和环境产生事实。判断、追加日志、更新投影在同一个 SQLite 事务里完成，写完才应答。时钟、随机数、规则文件和网络都由外壳送进来。同样的输入永远得到同样的事实，重放日志不会重新执行规则。

「为什么这一轮会这样」因此是可查询的事实。`agent-autoloop why` 和 `/v1/stream` 读的就是这条日志。

### 等待被做成了数据

要问人，这一轮就结束。问题、选项、建议和留给下次自己的 `about` 写进卡片。三天后回答，系统把回答变成一条普通事件，再开一轮，尽量接上原来的会话。会话接不上就开新会话，靠资料文件继续。会话是缓存，资料文件才是退路。

定时复查、失败重试、租约和离线判断共用一张到期表。外壳只负责下一次什么时候响。时间、人的决定、外部系统和 Agent 自己发出的事件走的是同一条路。

### 回执是事务，写错回执不重做业务

Agent 想让中台做的事全部写在最后一条消息里：提问、通知、结案、复查、再发事件。内核在一个事实里一次应用。`failed` 只会留下通知，提问和发事件不会生效，避免没跑成却把世界改了一半。

回执的 JSON 写坏了，接单程序在原会话里只要求重写最后一条消息，最多两次，并明确说不要调用工具。还是读不懂，就保留第一行结论，回执作废，发一张卡片告诉你原文在哪。已经做过的业务不会因为格式错误被自动重跑。

### 谁能做什么，是密钥分出来的

来源密钥只能以自己的名义发事件。接单程序密钥只能领交给它的活。一轮的 token 只能报告这一轮这一次执行，重复领取会让上一份 token 立刻失效。通道密钥只能领卡片、报告送达、转达允许名单里的人的回答，还要核对原消息。卡片链接只能回答那一张卡。本人密钥能看、能答、能停，但不能发事件、不能领活、不能改规则。规则只存在文件里。

日志里不存这些 token。轮次 token 和卡片链接用本机主密钥做 HMAC 推导。

### 别人写的字进不了指令通道

事件正文放在标明「是资料」的文件里。提示词里只有来源名、类型、对象和链接，而且对象和链接在进门时就限制了字符集。事件里如果带了目录、Agent 或权限，直接拒绝。能发给下游的事件类型由规则的 `emits` 写死，回执改不了来源。Agent 交回的事件跳数加一，提问和复查不把跳数清零，超过 8 层只记录、不再派发。

这挡不住模型读完资料文件之后仍然听从里面的话。它限制的是最坏结果的范围：就算被带偏，也只能在这条规则给定的目录、权限和事件类型里活动。

### 同一件事会并到一轮里

排队期间新到的同一事项事件，挂到已经在排队的那一轮上。失败重派时，期间新来的事件并进去。同一事项同时只有一轮处于已领取。一组的并发数由 `parallel` 封顶。没活时接单程序长轮询，新活到来立刻返回；响应丢了，用同一个 claim 取回同一份活。结果交出去之后响应丢了，原样重放得到同样的确认，内容不同则拒绝。

### 失败表比功能表更完整

协议里先写了出了什么事会怎样：重复事件、丢响应、会话接不上、回执写错、接单程序重启、电脑合盖错过定时、两边同时点卡片、规则写错时旧规则继续跑。至少一次是明示的，所以有副作用的 Skill 必须先核实当前状态。

20 万步固定种子模拟、两台接单程序下全部动作顺序、真进程 SIGKILL、内核变异，查的是同一组不变量：事件不重复、同一事项不同时领两轮、不超出组并发、回答一定叫醒原事项、已经完成的回执不会再次生效、日志重放结果一致。这是在用测试守架构。

### 交付插件证明了这条边界扛得住

审查、等待检查、合并、发布、核对线上版本，是这条系统里最长的状态机，但它只是一个普通 Agent 进程。内核没有第二份队列、槽位或失败计数。项目设置只从 main 的固定提交读取。审查时不检出、不运行 PR 里的代码、测试、配置和 hooks，只把裸 Git 对象变成文字差异。合并前再读一次 head、main 和标签。发布成功必须和健康版本一起成立。后续只改文档，不能把还没发布的代码掩盖过去。

复杂度没有消失，它被留在了该在的插件里。

## 需要正视的张力

这些大多是这套赌注的代价。要改，得先决定愿不愿意改赌注。

**控制通道是自然语言。** 一轮的结局看第一行措辞，中台要做的事看最后一块 `agent-autoloop` JSON。模型把给人看的结论和给机器的 API 写在同一条消息里。重写回执把损失限制住了，但每接一个新模型，都要重新赌它会不会稳定交出这块 JSON。ACP 把会话和权限弄得更结构化，回执仍然是最后一段文字。若以后自己做 Agent，而又能要求对方装一个很小的约定，更稳的做法是把回执写成一个文件或一次工具调用，正文继续给人看。现在这种「任何能打印最后一条消息的命令都能接」的普遍性，就是用解析失败的概率换来的。

**不可逆动作的闸在提示词里。** 内核真正硬性执行的是：交给谁、工作目录、权限档位、允许发出的事件类型、能结哪些卡、跳数、密钥范围。`askFirst`（删数据、停服、花钱、对外发消息）只出现在提示词里，内核不会在 Agent 真的去删、去付、去发之前拦截。安全说明里也写了这一点。个人机器、默认 `edit`、副作用再问你，这个威胁模型是闭合的。一旦 Agent 能碰生产或钱，应该沿用 `emits` 的做法：把不可逆动作做成一种必须由规则允许、由内核点名的能力。

**同一事项有一条被接受的重叠窗口。** 接单程序还在线、但 5 分钟没再报某一轮时，这一轮标成不确定，组的名额放开，后来补交的结果照样收下。不变量保证的是「处于已领取的轮次里，同一事项只有一轮」，不确定的那一轮不算在内。进程在写出 pid 之前被强杀、或者本地记录丢了而进程还在，都可能让旧进程和新的一轮同时存在。协议把这件事算进「至少一次」，要求 Skill 先读世界再动手。优化方向是把「确认进程组已经没了」放进放开名额的条件里。

**长程记忆依赖厂商会话。** 资料文件里有事件、回答、到期复查、未结卡片和已经做过的决定，足够让新会话接着干。它没有一份由事项自己积累、有长度上限、重启后仍在的工作笔记。`about` 承担了这个角色，但只在「人要决定」或「到点要复查」时才存在。连续很多轮都在自动推进时，中间推理会留在 Claude 或 Codex 的会话里。会话一断，模型容易把资料文件里的旧话当成新指令，或者把做过的步骤重做一遍。若要补，应该补在事项上：一份只作为资料注入的笔记，由上一轮回执写入，下一轮只读。不要把它放进内核当 Agent 记忆，也不要让它影响路由。

**工作流状态机被故意留在外面。** 交付插件已经是证据。内核保持瘦是对的。缺的是给插件作者的一个更硬的步骤合同：每轮只做一步，先读外部系统的当前事实，再决定这一步，然后用 `later` 或新事件把事项留下。现在这份合同写在协议和 Skill 的散文里，模型遵守的程度因模型而异。类型化的「一步结果」不必进内核，放在插件约定里就够。

**单人、单文件、本机，是范围纪律。** 没有总览页、多租户、模型路由、插件市场和内核里的 Agent 记忆，是写明的。这些不该补进内核。真要多租户，或者让模型自己决定下一轮交给谁、在哪个目录、用什么权限，会直接打穿现在最值钱的几条不变量。多 Agent 协作的正道是：这一轮按 `emits` 发出事件，另一条规则再派。路由权始终留在规则文件里。

## 以后自己设计 Agent 时可以拿走的

1. 先定六个词，再写循环。分清「一次执行」和「一件会跨很多天的事」。等待、重试、人的决定都是事件，执行过程不阻塞。
2. 模型不握路由权。目录、权限、用哪个模型、能产生什么副作用，来自一份模型改不了的规则。模型的输出只在这份规则划定的范围内生效。
3. 把不可信文本和指令分成两个通道。进提示词的字段用字符集收紧。正文放进文件，并在提示词里写明那是资料。默认权限取能完成任务的最小一档。
4. 副作用进一个事务型回执。提问、通知、结案、延迟、再发事件一起成功或一起被拒。解析失败只重写回执。失败的一轮不要让一半动作落下去。
5. 按至少一次来设计每一步。稳定的事件编号、领取幂等、结果重放、第一次回答算数。每个有副作用的动作开始前先读外部世界的现状。
6. 给人的注意力单独计价。默认安静。只有规则点名的事和只有人能解开的阻塞才发卡片。同一件事的卡片用稳定的 key 去重。卡片发出去之后，进程退出。
7. 跳数从第一天就加上。Agent 产生的事件会再进入 Agent。人工回复和定时复查不要把计数清零。到了上限就留下记录并通知人。
8. 会话当成缓存。续不上会话时，系统仍然能只靠资料把事做完。续上了只是更省。
9. 凭据按能力拆开。来源、执行者、一轮、通道、一张卡片、本人，各持各的。日志里不放能直接使用的秘密。
10. 内核保持可重放，产品知识放插件。判断函数不读时钟、不碰网络。插件主动连进来。一个新系统只是一种新的事件翻译。
11. 先写失败表和不变量，再写功能。至少包括：重复投递、响应丢失、进程被杀、回执损坏、人点了两次、规则写错、旧的执行者晚到。能用一个固定种子把这些交错跑一遍，架构就很难在以后的改动里被悄悄改坏。

若只记一句话：Agent 可以不确定，调度机器必须确定。模型负责这一轮怎么做，机器负责这件事还在不在、谁有权做、做成之后留下什么。
